# ストア審査・掲載

## 名前と言葉

- 名前は両方のストアで早めに確かめる。「RestCall」は App Store で取られていて、EAS が「RestCall (80ac1c)」を付けた。名前の先頭が既存のアプリと同じだと弾かれることもある
- App Store のキーワード・名前・サブタイトルは版を出すときにしか変えられない。最初の申請の前に、Apple の検索候補と順位で言葉を決める。NoPace は後から直すために審査を取り下げて出し直した
- Play は説明文も検索の対象。名前（30字）と短い説明（80字）に実際に探される言葉を入れる
- 名前とサブタイトルが検索結果で切れないかを ASC の「デバイスプレビュー」で見る

## App Store

- 審査に出すのは production プロファイルのビルドだけ。TestFlight 用（デバッグと開発用 OTA 入り）を出して、本番で誰でも Pro を無料にできた
- 新しいアプリは、TestFlight の招待メールで一度承認しないと TestFlight アプリに出てこない
- 有料 App の契約（Paid Applications Schedule）の更新に同意しないと、新しい版の提出と課金アイテムの作成が止まる。同意できるのはアカウント保有者だけ。課金を作る前に ASC の「ビジネス」で確かめる
- 初めての非消耗型の課金は、アプリの版と一緒に審査に出す。審査用のスクショがないと「メタデータ不足」になる
- ファミリー共有は一度オンにすると戻せない
- 審査メモは版を複製すると前の版のものが残る。毎回書き直す
- iOS の「新機能」やメタデータに Android のことを書くと 2.3.10 で却下される
- 購入の失敗をモーダルの裏に隠すと 2.1 で却下されうる。失敗は必ず見える形で出す
- 初回起動の `AppTransaction.shared` で、Sandbox や TestFlight のサインインを求められることがある（「サインイン不要」の審査メモと食い違って見える）
- 審査用の録画: 電源ボタンでロックすると画面収録が止まる。Apple Music の音は無音になる。ロックせずに通知センターを出して撮り、音はスピーカーで鳴らしてマイクで拾う
- ログインが切れると Claude はパスワードを入れられない。提出は ASC API（GitHub Actions など）でできるようにしておく
- `eas submit` が「Something went wrong」と出ても届いていることがある。逆に `--auto-submit` で上がっていないこともある。提出のあとはストアの API でビルドがあるかを確かめる
- ネイティブの変更が多い版は、7日間の段階的リリースを使う
- パスワード管理の拡張機能の小窓が入力欄に出て、保存されていなかったことがある。保存できたかを画面で確かめる

## Google Play

- 「管理対象の公開」がオンだと、審査が通っても「公開」を押すまで出ない
- 課金の商品は、課金（BILLING 権限）入りのビルドをどこかのトラックに一度上げないと作れない
- AAB（74MB）はブラウザから上げられない。API 用のサービスアカウントで上げる
- 未公開のアプリでは掲載情報の API が 403 になることがある。新しいサービスアカウントの権限は反映まで時間がかかる
- 審査中に次の AAB を上げると、トラックのリリースが丸ごと置き換わり、審査中の版が外れる
- 前面サービス（Foreground Service）の申告には動画のリンクが必須。画面録画の「デバイスの音声」で録れるのはメディアの音だけ。種類を決めた時点で撮り方まで決める
- 申告（コンテンツのレーティング、データ セーフティなど）は答えを見直す。ランダムなアイテムの購入を間違えて答えた
- RevenueCat が Billing の権限を入れるので、課金を使っていなくても「アプリ内購入あり」と出る
- 英語のリリースノートは500文字まで
- 内部テストはテスターがいないと非アクティブになる。Android の確認を内部テストでやると、本番の端末が確認前の版に置き換わる。確認は別 ID の開発用アプリで行う
- 下書きの古い版だけは外せない。「変更を削除」は審査中のものまで消す
- R8 の mapping を上げないと警告される
- Android デベロッパーの確認（署名鍵の登録）の期限がある

## スクショ

- 本番と同じビルドで撮る。開発用だとデバッグのボタンが写り込む
- StoreKit の設定の値段（$3.99）がそのまま写る。地域と値段を日本に合わせてから撮る
- デバッグツールにスクショ用のサンプルデータを作る機能を入れる
- 素材は `store/raw` にまとめ、ストアとアプリ内の使い方の両方で使う。使い方の画面のスクショはすぐ古くなる
- 説明・LP・利用規約・スクショと実物を合わせる（「すべて無料」と書いたまま Pro を出した）
- スクショは審査を通さないと差し替えられない。提出の下書きに入っている間は編集できない
- Play にまとめて上げると逆順に並ぶ
- ストアの文言やスクショの変更は、前の版と並べたアーティファクトで見せる

## レビューへの返信

- 返信済みかどうかは Expo MCP の結果に出ない。投稿の前に ASC API で確かめる
- `appstore_reply_review` は下書きではなくそのまま投稿する。文面の OK をもらってから送る
- 自分で評価を付けるのは規約違反
