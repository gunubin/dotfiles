# UI・UX

## モバイルの基本（最初の画面から守る）

RestCall で「基本ができてないよ！！」と言われて全画面を点検した。画面を作ったら次を見る。

- 入力欄がキーボードに隠れない。キーボードの高さはナビゲーションバーの分を引いた値で返ってくる
- 下の安全領域とナビゲーションバー: オンボーディングのボタン・モーダル・ボトムシート・詳細の下端で4回指摘された。土台の部品で足す
- 保存の二度押しで下の画面まで閉じない
- 書きかけを戻るで黙って捨てない
- 押す範囲を見た目より広げる（hitSlop）。押し間違えやすい位置にボタンを置かない
- 固定の高さを使わない（カードの高さや minHeight で余白ができた）。シートの高さは画面ごとに測らず固定の割合にする（「たまにすごい低い」）
- ライトとダークの両方で見る。境目が溶ける、明るいボタンの上の白い文字が読めない、ダークで案内の帯が見えない、が起きた。ライトはカードとの差が見えるよう背景を少し暗くする
- キーボードは実機と同じ全幅の Gboard で確かめる。テスト用の IME では隠れ方が再現しない

## OS ごとの落とし穴

- 片方の OS 向けの直しは Platform で絞る。iOS 向けにキーボード中の余白を消したら Android で保存ボタンが隠れ、「測って伸ばす」直しを入れて「無理やり」と言われた。ライブラリの作りと直前の変更を先に疑う
- アプリ内でテーマを切り替えるなら `Appearance.setColorScheme` で OS に伝え、ヘッダーに `headerUserInterfaceStyle` を指定する。伝えないと iOS のガラスのボタンやキーボードが白く出る。最新の iOS は実機で見る
- iOS 26 のヘッダーのガラスの枠（44pt）より大きいボタンははみ出す。単独のアイコンが左に寄る、ボタンが横長に伸びる
- トーストやダイアログが iOS のネイティブモーダルの裏に隠れる。確認は OS の Alert、選ぶ・書くはネイティブの formSheet にする
- RN の Modal を続けて開くと透明な膜が残って押せなくなる
- formSheet の中の一覧: iOS は最初の ScrollView をシート全体に広げる。Android は `nestedScrollEnabled` が要る
- Android の FlatList で `removeClippedSubviews` と sticky header を組み合わせると、スクロール後に押せなくなる
- 数百個の要素は一度に描かず FlatList にする
- Android の `headerTitleAlign` は既定が中央ではない。ロゴを左に置くなら headerLeft か画面の中に置く
- Android で押したときの表示が丸の背景色を上書きする、角丸の View にあとから背景色を足すと四角になる、背景色の付け外しが反映されない。状態で値だけ変え、スタイルの有無を変えない
- 日本語の太字が行の高さで欠ける、日本語の見出しが下寄りでバッジとずれる
- NativeTabs はネイティブのアイコンが要る
- Android の描画は release ビルドの実機で確かめる。エミュレーターの開発ビルドで直ったと言って、本番の実機で直っていなかった

## ユーザーが繰り返し言った好み

- 動きは指に合わせ、バネで弾ませない。並び替えは速く（0.24秒ほど）、弾みは控えめ
- 1回の操作で済ませる。スワイプ1回でキーボードとシートの両方を閉じる
- シートは選んでも閉じない。後ろの見え方を見ながら選べる。選んでいるものをもう一度押すと閉じる。スクロール中の下スワイプで閉じない
- 追加と選択を同じシートにしない。一覧を見ながら直すもの・キーボードを使うものは普通のページにする
- 同じ部品は画面ごとに仕様をそろえる（「カレンダーが各所で仕様違うのは困る」）。振動もそろえる
- 並べ替えはボタンではなくドラッグ（「手抜きしないで」）
- グリッドは横幅いっぱいに詰め、最後の段を歯抜けにしない。右余白はほかとそろえる
- 情報を重複させない。同じ設定を2か所に置かない
- 状態の表示と操作を分け、操作は目立たせすぎない
- 状態が変わったことは、新しいトーストを重ねず、その場の入れ替えで伝える
- 押し間違いの重さでボタンが要るかを決める
- 焦らせない（期限切れを赤や件数で責めない）
- ブランドの色を土台にする（「なんで緑？」）
- Pro の人への表示は控えめに（札だけ）
- 空の状態を寂しくしない
- 文言: 普通の言い方にする（「最新の版に更新しました」→「アプリをアップデートしました」）。括弧が続くラベルは嫌い。完了のトーストは何をしたかが分かる文にする。見出しはキャッチコピーではなく何のアプリかを言う
- 操作の教え方: トーストで操作を教えない。いきなり図を見せず、ボタンを照らして吹き出しで教えて実際に押してもらう。吹き出しには指す先がわかる矢印。同じものを2回見せない。説明なしに「はじめる」を押させない。流れの図は設定の「使い方」に置く
- 選ぶものは試してから選べるようにする（声は押したら喋る）
- 案には識別子（A・B…）を付けて、アーティファクトに並べて選んでもらう
- 承認されたデザインは要素ごとに漏れなく実装し、配置も合わせる。色だけ変えて「その案にした」と言わない
- 新しい画面で既存の使い勝手（スワイプなど）を落とさない。既存の部品を使い回す
- ストアのスクショは売りに絞る
- Web はスマホの幅で見る
