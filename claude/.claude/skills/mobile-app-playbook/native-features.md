# 通知・ウィジェット・バックグラウンド・時刻・データ

## 通知

- 通知を既定でオフにし、許可を作成画面の奥で聞いていたら、許可した人は初めて開いた人の2割弱だった。最初の記録などを保存した直後に一度だけ提案し、届く時刻を具体的に書く（「10月19日の 9:00 に届きます」）
- トグルを押しても OS の許可を求めない経路を作らない
- Android の厳密でないアラーム（window 付き）は最大1時間ほど遅れる。決まった時刻に促すなら `SCHEDULE_EXACT_ALARM` と Play の申告を最初に決める
- Android 16 では文字が空のアクションのボタンは消える。アイコンだけで出せるのは Android 17 から（それでも枠付き）。他のアプリでアイコンだけに見えたのは OS のスヌーズのボタンだった
- 押し間違えると困るボタンは通知に置かない
- 通知の進捗バーは進んだところだけ色を付ける。アイコンはバーと別の色にする
- 新しい OS の通知（進捗・Live Update）は対象 OS のエミュレーターで撮って確かめる

## ウィジェット

- 削除・全データの削除・0件のときもウィジェット用のデータを必ず更新する。削除したものがウィジェットに残った
- 日付の計算はウィジェット側に置き、テストする。アプリ側で計算すると、アプリを開くまで日付が進まない
- Swift はミリ秒付きの日付を読めないことがある。並びは同点のときの順を決めておく
- ネイティブ側にも文言ファイル（Localizable.strings・.stringsdict）を置く。ないと英語の端末でも日本語で出る。英語の単数・複数（「Every 1 days」）も
- 置いた数の計測は2回続けて同じ数のときだけ記録する（置いた直後は多く数える）
- iOS のウィジェット一覧では、名前が同じだと見分けにくい。入れ直した直後は一覧に出ない
- Android のウィジェットの裏の処理（WorkManager）は R8 に削られる。`extraProguardRules` に keep を最初から入れ、release ビルドで確かめる
- ウィジェットを置く操作など、Claude ができる確認はユーザーに頼まない

## iOS のバックグラウンドと音

- 画面を消すと音のセッションの切り替えが断られる（561015905・560557684）。電話の割り込みのあと復帰の知らせが来ないことがある
- TestFlight で入れた実機はログが見えない。アプリの中に記録を残してデバッグツールからコピーできるようにする
- Live Activity には OS がアプリ名やアイコンを付けないので自分で描く

## 時刻

- 時刻の入口を1つにまとめる（`AppClock.now()`・`AppDay`）。`new Date()` で今日を決めている箇所が109あり、深夜の記録が翌日扱いになって直すのが大変だった
- デバッグツールで時刻をずらせるようにする。iOS のシミュレーターは時刻を変えられない。通知の予約とウィジェットは実際の時刻のまま
- 記録の時刻は押した瞬間の値を入口から取る。比べるために作った「今日の0時」をそのまま保存して、完了の時刻が 0:00 になった
- 日付だけの値を UTC の0時として読むと、日本時間の0〜9時で1日ずれる。jest は TZ を固定する
- アプリが開いたまま日付やタイムゾーンが変わったときに、日付の状態を作り直す（旅行先で「エラー」だけのトーストが出た）

## データの保存とバックアップ

- 新規インストールで DB のマイグレーション前に「準備完了」を出し、`no such table` になった。初期化は Promise を共有して完了を待ち、まっさらな状態でも試す
- iOS の AsyncStorage は既定で iCloud のバックアップから外れている（`RCTAsyncStorageExcludeFromBackup`）。Info.plist で含める
- Android の Auto Backup は25MBまで。OTA のファイル（1版 11MB が2版）を外す
- 機種変更でデータが移るかと、書き出し・読み込みを両 OS で確かめる
- 大量データ（1年分）の試験用ファイルを用意する。1年分を読み込んで初めて出た不具合があった
- 「すべてのデータを削除」などの処理を `__DEV__` のときだけ動く作りにしない
