# OTA・配信

OTA は EAS Update ではなく Revopush（CodePush 系）。expo-updates は iOS で OTA を当てると落ちたのでやめた。

## 最初に決めること

- チャネルを本番（Production）と開発（Staging）に分ける。本番は手で昇格させる
- **コード署名を最初のストアビルドから入れる**。署名がないと、アクセスキーが漏れたときに全員へ任意の JS を配れる。あとから入れるにはストアのビルドからやり直しになる
- 配信サービスに2段階認証を付け、鍵は本番と開発で分ける
- CI 用のキーは既定で60日で切れる。`--ttl 1y` で作る
- 本番は「5分以上離れて戻ったとき（ON_NEXT_RESUME）」に当てる。すぐ当てると使っている途中で再読み込みされる
- 自動配信は release ブランチだけにする。機能ブランチの push ごとに配って GitHub Actions の月の枠を使い切り、PR の CI と審査提出まで止まった。それ以外は手元から配る

## 手元ビルドの Android で OTA が当たらない

- 症状: 差分の適用が毎回「This file can not be opened as a file descriptor」で失敗する
- 原因: リリースビルドが資源の名前を縮める（`res/-B.png`）のと、APK の中の CodePush の目録が圧縮されるの2つ
- 対処: 両方を config plugin で切る（RestCall の `plugins/withAndroidBuildTweaks.js`）。それまでの APK には二度と届かない
- `.xml` のアセットがあると Android の OTA が「data integrity check」で取り消される

## 届いたかの確かめ方

- `adb logcat | grep CodePush` で「update success」を見る。Revopush のインストール数は当てにならない
- 届くのは「2回開き直して」から。確認を頼むときは毎回そう書く
- ユーザーが「直っていない」と言ったら、まず設定の OTA の番号を見てもらう

## ネイティブを変えたとき

- OTA は `version` が同じバイナリに届く。ネイティブを足した JS が古いバイナリに届くと、ない関数を呼んで落ちる（AsyncStorage 3 で毎回オンボーディングが出た、expo-sharing で起動時に落ちた）
- ネイティブ（モジュール・ネイティブのパッケージ・起動画面・アイコン・ウィジェット）を変えたら `version` を上げて開発ビルドを作り直す
- それでも古いバイナリに届きうる画面では、ネイティブの関数があるか確かめてから呼ぶ
- 手元のエミュレーター・シミュレーターのバイナリが古くないかも確かめる
- 版を上げたあとで前の版の本番に出すときは `--version <前の版>` を付ける
- ウィジェット（Swift・Kotlin）の変更は OTA で届かない

## 配信先は丸ごと置き換わる

- 本番の OTA はバンドルを丸ごと置き換える。一部の変更だけのブランチから出すと、すでに出した変更が消える。既出の変更をすべて含むブランチから出す
- 開発用（Staging）も1本しかないので、最後に push したブランチで上書きされる。確認中に別のブランチを push しない。確認はまとめたブランチから出す

## 通知

- 配信の完了は Slack の Incoming Webhook で知らせる。中身が同じで配信されなかったときに「配信しました」と言わない
- 手元からの配信で、前の回の一時ファイルが混ざってサイズの上限で止まったことがある。一時フォルダは毎回作り直す
