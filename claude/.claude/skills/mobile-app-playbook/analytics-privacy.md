# 分析・プライバシー

## 計測の作り

- **初期化前のイベントは捨てられる**。`analytics_auto_collection_enabled:false` のうえ Firebase の初期化を待たずに画面を出していて、オンボーディングの開始が0件だった。送信をキューにためて、初期化が終わったら（成功でも失敗でも）流す
- 自動のスクリーン計測を切る。手動と重なり、RNSScreen や UIViewController の名前が大量に出た
- カスタムディメンションは文字列の値しか拾わない。メモリに残したあとも数値で送って再発した。`logEvent` の型でパラメータを文字列に強制する
- カスタム定義は作った日からしか集計されない。最初のリリースの前に一覧を決めて登録する
- `source` などの予約名を使わない（キャンペーン計測と衝突した。`entry_point` にした）
- イベントは UI ではなく、処理が成功したあとに UseCase から送る。UI から送ると別の画面からの操作で漏れ、失敗しても送ってしまう
- 表示から購入までの全段に流入元を付ける
- 判断に要る操作を最初から測る（月送り・絞り込みなど、測っていなくて決められなかった）
- 自由入力の文字は送らない。列挙値だけを送り、テストで担保する。健康データのメモは特に送らない
- 落ちないエラーも中身を残す（Crashlytics の non-fatal など）。「エラー」とだけ出るトーストで原因を追えなかった

## テスト端末を除く

- 開発用アプリは `traffic_type=internal` と GA4 の Internal Traffic のフィルタで除く。最初の版から入れる
- Play の事前リリースレポート（`firebase.test.lab`）の端末では分析を止める。国が空か (not set) の IN2025・OnePlus8Pro など
- Apple の審査端末（米国の iPhone 16 Pro Max・iPad）も混ざる
- 数字を出すときは除く端末を必ず除く。テスト端末込みの数字を出して撤回したことがある
- ASC の「概要」は90日分。リリース日は既存ユーザーのアップデートで数字が跳ねる

## 権限

- Firebase を入れると `AD_ID` と `ACCESS_ADSERVICES_AD_ID` が入る。広告を使わないなら app.json で外し、Play の申告も「使わない」にする

## プライバシーポリシー

- 外部に送るものを全部書く。Revopush が Android ID を送ること、課金を足したあとの RevenueCat が漏れていた
- 別のアプリからコピーしたら、リンクの定義がそのアプリの URL のままになっていた。URL を開いて確かめる
- ポリシーに書いた保持期間と GA4 の設定を合わせる（GA4 の初期値は2か月。14か月に変えた）
- ポリシーを変えたら、アプリ・ストアの申告（データ セーフティ・App Privacy）・LP をそろえる
- サイトの自動デプロイが止まっていて、ポリシーが本番に出ていなかった。マージの前にプレビューの成功を確かめ、公開後に URL を開く。ストアに登録した URL が 404 だったこともある

## EU

- 分析に同意を取る画面がないなら、配信国から EEA と英国を外す。ePrivacy 指令の主流の見方では、端末のデータを使う分析には同意が要る
- EU に広げるときは、初回に同意を取り、同意するまで分析を送らない作りを先に入れる
- 分析を送らない版（RestCall の iOS 1.0）は EU にも出せる。CallKit を使うなら中国本土を外す
