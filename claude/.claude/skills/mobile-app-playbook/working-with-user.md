# Claude の進め方

NoPace と RestCall でユーザーが不満を言ったこと。モバイルの作業で起きやすいので、ここに置く。

## 確かめてから言う

- 画面を見てから「直った」と言う。グリッドを見ずに「ご希望どおり」と報告して崩れていた。種目のシートを「修正指示したよね？」と言われた
- 再現してから直す。「エミュレーターがつながっていない」として推測の PR を出し、「エミュレータ繋げばよくない？」と言われた。再現したら原因は別だった
- 確かめずに「できない」と言わない。「ローカルビルドも無料枠を使う」と言ったが根拠がなかった。「Google の決まりで API ではできない」と渡そうとして「前はそっちがやってくれたよ！チャレンジして！」と言われた
- 確かめていない事実を書かない。推測で書いた理由をプロジェクトの決定事項のように話した。記憶で書いた Sandbox の手順が効かなかった
- 提案の前にデータ（GA4・レビュー・ランキングの MCP）とこれまでの決定（ロードマップ・Issue・メモリ・以前のやり方）を見る。「なんで mcp つかわんの？」「20分も待つのはありえない、以前はそれでやってた」

## 頼み方と報告

- 判断してほしいことは1行で書く。「僕はなにを判断したらいいの？」「つまり何をしたらいいの？」と何度も言われた
- 機能の追加や範囲の変更を説明の中に紛れ込ませない。見出しで伝える（「機能追加するなんて今初めて知った」）
- ユーザーにコマンドを頼むときは前提（ブランチの切り替えなど）と、結果をどこで見るかまで書く（「親切にして欲しいです」）
- Claude にできる操作はユーザーに振らない（ウィジェットを置く、スクショの差し替え）
- 話がわからないときは推測で理由を並べず、質問する（「理解できないなら質問して」）
- 返答は日本語。ツールの英語の出力やスキルを読んだ直後に英語になりやすい

## 約束したことを落とさない

- 「すぐやる」と言った作業は、会話の要約（compaction）の前後で落とさない。帯やメモに残す（「すぐやるっていうてましたよね？」）
- 理由なく後回しにしない
- ユーザーが済ませたと言ったら帯（user-todos）からすぐ消す（「消したってさっき言ったよね？」）
- 「終わり次第やる」と言ったことは本当に終える。止まった処理を「ビルド中」と取り違えて待ち続けた
- 長く待つときは何を待っているかを伝える（「めちゃ時間かかっている理由は？」）。CI の完了をユーザーの前で待たない
- 定期チェックは間隔を長めにし、変化がなければ黙る（「変化なし」でチャットが埋まった）

## 外に出るもの・壊れるもの

- 公開される操作（レビューの返信、ストアの投稿）は文面の OK をもらってから
- マージの前にプレビューと CI の成功を確かめる。lint や Prettier のずれを残したまま push しない
- ビルド番号を勝手に触らない。未コミットの変更を残したら報告する
- ユーザーのシミュレーターやデータに手を出さない。agent-device の `find` は既定でタップする（`is exists` を使う）。データは一覧の何番目かではなく ID で操作する
- 一時バックアップを /tmp に置かない。スクリプトで一括で消すときは範囲を確かめる。Prettier を全体にかけない
- 作業はそのアプリのフォルダで行う（dotfiles のフォルダで RestCall を作り、あとで引き継ぎになった）

## 外出中

- ユーザーは外出中にスマホから作業を頼むことがある。1Password の認証・鍵の受け渡し・IAM の権限付けなど Mac が要る作業は、スマホでの手順を出すか、帰ってからに回す
